# 容器化与本地开发环境设计

## 任务概述

为 image-text-analyzer 项目（Spring Boot 3.2 / Java 17 / Maven）添加容器化支持和本地开发环境，包括：

1. Dockerfile（多阶段构建 + 分层优化）
2. docker-compose.yml（应用 + PostgreSQL + Redis + MinIO + Keycloak）
3. CI 优化（去除无用权限 + Docker 构建验证）
4. 文档更新

## 技术方案

### 1. Dockerfile 设计

#### 多阶段构建策略

```dockerfile
# 阶段 1: 构建阶段（Maven + JDK 17）
FROM eclipse-temurin:17-jdk-alpine AS builder
- 先拷贝 pom.xml 并执行 mvn dependency:go-offline
- 利用 Docker 层缓存，避免每次代码变更都重新下载依赖
- 再拷贝源码并执行 mvn package

# 阶段 2: 分层提取阶段
- 使用 Spring Boot layertools 提取 JAR 分层
- 将 dependencies、spring-boot-loader、snapshot-dependencies、application 分开

# 阶段 3: 运行阶段（JRE 17 精简镜像）
FROM eclipse-temurin:17-jre-alpine
- 创建非 root 用户（spring:spring，UID 1000）
- 按顺序拷贝各层（利用层缓存，dependencies 变化最少，放最前）
- 设置 JVM 容器参数：-XX:MaxRAMPercentage=75.0
- 暴露 8080 端口
- 以 spring 用户运行
```

#### .dockerignore 配置

排除不必要的文件：
- target/（构建产物）
- .git/（Git 历史）
- .idea/、.vscode/（IDE 配置）
- *.md（文档）
- .env、.env.*（敏感配置）

### 2. docker-compose.yml 设计

#### 服务架构

```yaml
services:
  app:
    - 依赖所有基础服务（PostgreSQL、Redis、MinIO、Keycloak）
    - 使用 depends_on with service_healthy 条件
    - DASHSCOPE_API_KEY 从 .env 注入
    - 端口 127.0.0.1:8080:8080（仅本地访问）
    
  postgres:
    - 镜像: pgvector/pgvector:pg16
    - 用户名、密码从 .env 读取（${POSTGRES_USER}）
    - 端口: 127.0.0.1:5432:5432
    - 命名卷: postgres-data
    - healthcheck: pg_isready
    
  redis:
    - 镜像: redis:7-alpine
    - 密码从 .env 读取
    - 端口: 127.0.0.1:6379:6379
    - 命名卷: redis-data
    - healthcheck: redis-cli ping
    
  minio:
    - 镜像: minio/minio:latest
    - root 用户/密码从 .env 读取
    - 端口: 127.0.0.1:9000:9000, 127.0.0.1:9001:9001
    - 命名卷: minio-data
    - healthcheck: curl /minio/health/live
    
  keycloak:
    - 镜像: quay.io/keycloak/keycloak:latest
    - admin 用户/密码从 .env 读取
    - 端口: 127.0.0.1:8180:8080
    - 命名卷: keycloak-data
    - healthcheck: curl /health/ready
```

#### 安全配置

1. **所有敏感信息从 .env 读取**：
   - POSTGRES_USER、POSTGRES_PASSWORD、POSTGRES_DB
   - REDIS_PASSWORD
   - MINIO_ROOT_USER、MINIO_ROOT_PASSWORD
   - KEYCLOAK_ADMIN、KEYCLOAK_ADMIN_PASSWORD
   - DASHSCOPE_API_KEY

2. **端口绑定安全**：
   - 所有端口绑定到 127.0.0.1，不暴露到外网

3. **.env.example**：
   - 提供占位值（如 your_password_here）
   - 提交到 Git 作为模板

4. **.gitignore**：
   - 已包含 .env 和 .env.local（验证并确认）

#### 本地开发支持

通过 profile 或注释说明两种启动方式：

1. **完整启动**（应用 + 所有服务）：
   ```bash
   docker compose up
   ```

2. **仅启动依赖服务**（方便 IDE 调试应用）：
   ```bash
   docker compose up postgres redis minio keycloak
   # 然后在 IDE 中启动 Spring Boot 应用
   ```

### 3. CI 配置优化

#### 修改 .github/workflows/ci.yml

1. **去除无用权限**：
   ```yaml
   permissions:
     contents: read
     # checks: write  # 删除：没有步骤使用此权限
   ```
   
   理由：检查代码发现没有任何步骤需要写入 checks（如 test-reporter、check-run-reporter 等），遵循最小权限原则。

2. **添加 Docker 构建验证**：
   
   新增 job: `docker-build`
   ```yaml
   docker-build:
     name: Verify Docker Build
     runs-on: ubuntu-latest
     steps:
       - Checkout code
       - Set up Docker Buildx
       - Build Docker image（不推送）
       - Validate docker-compose.yml（docker compose config）
   ```

   注意：不使用真实 DASHSCOPE_API_KEY，设置 dummy 值。

### 6. 分支保护配置

#### 目标

为 main 分支开启保护规则：
- 要求 PR 合并前通过 CI check
- CI check 名称：`Build and Test`（来自 ci.yml 的 job name）
- 如有必要开启 strict mode（要求 PR 分支为最新）

#### 实施方式

使用 GitHub API (gh api) 或 rulesets API：

```bash
gh api \
  --method PUT \
  repos/{owner}/{repo}/branches/main/protection \
  -f required_status_checks[strict]=true \
  -f required_status_checks[contexts][]=Build and Test \
  -f enforce_admins=false \
  -f required_pull_request_reviews=null \
  -f restrictions=null
```

#### 预期结果

- 成功：返回 200，分支保护已生效
- 失败：
  - 403 Forbidden：当前凭据无管理员权限
  - 404 Not Found：仓库不存在或无权限
  
  此时在报告中说明：
  - 需要仓库管理员权限
  - 手动配置路径：Settings → Branches → Add rule
  - 需要配置的 check 名称：`Build and Test`

## 技术要点总结

### Dockerfile 优化

1. **依赖层缓存**：先拷 pom.xml 预取依赖，源码变更不重新下载
2. **分层 JAR**：使用 Spring Boot layertools，依赖层变化少，应用层变化频繁
3. **精简镜像**：JRE alpine（~200MB vs JDK ~400MB）
4. **安全运行**：非 root 用户（UID 1000）
5. **容器优化**：MaxRAMPercentage 自适应容器内存限制

### docker-compose 最佳实践

1. **服务依赖**：depends_on with service_healthy 确保启动顺序
2. **健康检查**：所有服务配置 healthcheck，避免应用启动失败
3. **数据持久化**：命名卷（volumes）而非绑定挂载
4. **安全配置**：密码环境变量化，端口本地绑定
5. **开发友好**：支持只启动依赖服务

### CI/CD 改进

1. **最小权限**：去除未使用的 checks: write
2. **构建验证**：确保 Dockerfile 和 compose 配置正确
3. **快速失败**：Docker 构建问题在 PR 阶段就发现

## 潜在问题与解决方案

### 问题 1：Maven 依赖下载慢

**解决方案**：
- Dockerfile 中配置阿里云 Maven 镜像
- 或使用 .m2/settings.xml 挂载

### 问题 2：应用启动时数据库未就绪

**解决方案**：
- 使用 depends_on service_healthy（已实施）
- Spring Boot 配置连接重试

### 问题 3：本地 Docker 构建失败

**解决方案**：
- 检查 Docker daemon 是否运行
- 检查磁盘空间
- 如果是 VM 环境限制，在报告中说明

### 问题 4：分支保护权限不足

**解决方案**：
- 在报告中清晰说明需要的权限和手动配置步骤
- 不尝试绕过权限限制
